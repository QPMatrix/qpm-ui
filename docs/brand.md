# Brand

The QPMatrix brand identity — the mark, the two lockups, and the favicon set
generated from them. This is reference (facts about this repo's assets and
how to use them), not a design-system component: nothing here ships through
the shadcn registry, because none of it is source a consumer installs and
edits — it is static collateral a consumer copies as-is, the same way a
company logo is never "componentised."

## Assets

All source assets are owner-approved AI-generated artwork, committed
byte-for-byte from the approved masters — never edited or regenerated by
tooling. They live in [`packages/tokens/brand`](../packages/tokens/brand)
(`@qpmtx/tokens`'s own `brand/`):

| File                                               | Size                      | Use                                                                                                                    |
| -------------------------------------------------- | ------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `qpmatrix-mark.png`                                | 1024×1024                 | The mark alone — favicons, app icons, an avatar, anywhere the wordmark does not fit.                                   |
| `qpmatrix-lockup-dark.png`                         | 1920×1080                 | Mark + "QPMatrix" wordmark on the graphite ground. Default lockup — QPMatrix surfaces are dark-first.                  |
| `qpmatrix-lockup-light.png`                        | 1920×1080                 | The same lockup on a white ground, for a light-mode-only surface (a printed document, a partner's light-themed embed). |
| `favicon/favicon-16.png`, `favicon/favicon-32.png` | 16×16, 32×32              | Browser-tab favicon sizes.                                                                                             |
| `favicon/apple-touch-icon-180.png`                 | 180×180                   | iOS/Safari home-screen icon.                                                                                           |
| `favicon/icon-512.png`                             | 512×512                   | PWA manifest icon / high-DPI app icon.                                                                                 |
| `favicon/favicon.ico`                              | 16/32/48 multi-resolution | Legacy `<link rel="icon">` target.                                                                                     |

The favicon set is a **derived** output — resized copies of `qpmatrix-mark.png`
at fixed web-standard pixel sizes, generated with `sips`/ImageMagick
(`magick <mark> -resize <NxN> <out>.png`; the `.ico` via
`-define icon:auto-resize=16,32,48`). Resizing is not "editing the artwork":
no pixel of the mark's own composition was redrawn, retouched, or
regenerated — the same rule that governs the mark and the lockups applies to
every derived size.

**No hand-authored SVG ships here.** The mark's gradient tile fills and soft
per-tile highlight blooms are a product of the AI render, not a small set of
flat shapes; a hand-built vector approximation could get close but not
pixel-faithful, and this brief's own instruction is PNG-only unless a vector
reproduction is faithful. Shipping a "close enough" SVG that consumers then
treat as canonical is a worse outcome than shipping none — a future task with
the budget to trace the exact gradient stops and rounded-rect geometry against
the raster original can add `qpmatrix-mark.svg` deliberately, not as a
side-effect of an unrelated change.

## Palette

The mark's three colours are already `@qpmtx/tokens` roles — nothing here is
a new value, only a naming of which existing tokens the brand identity is
built from:

| Role in the mark    | Token                                                                        | Dark value | Light value                                                                                                            |
| ------------------- | ---------------------------------------------------------------------------- | ---------- | ---------------------------------------------------------------------------------------------------------------------- |
| Primary tile violet | `--brand-strong` (`--violet-600`)                                            | `#7C3AED`  | `#6426C7`                                                                                                              |
| Accent tile cyan    | `--cyan-400` (raw palette step — no semantic `brand-accent` role exists yet) | `#22D3EE`  | `#22D3EE` (raw steps are theme-invariant)                                                                              |
| Canvas / background | `--bg-subtle` (`--graphite-950`)                                             | `#0D1117`  | — (light lockup uses `--graphite-0` / `#FFFFFF` instead, a deliberate different surface, not this token's light value) |

The rendered mark's own pixels sample within a few points of these hexes
(measured: violet ≈ `#7F41F8`, cyan ≈ `#23D4F0`, background exactly
`#0D1117`) — the small drift on violet and cyan is the AI render's own
gradient/lighting, not a different intended colour. Treat the token values
above as canonical; do not eyedrop a slightly different hex from the PNG.

## Clear space

Minimum clear space on every side of the mark or the lockup is **one tile
width** — the mark's own 3×3 grid is built from ~182px tiles in the 1024px
master, so the rule is "leave room for one more tile" on each edge. The
committed master files already exceed this (the mark sits with roughly 1.3
tile-widths of padding baked in), so placing either asset directly against a
UI container edge with no additional margin already satisfies the rule; do
not crop closer than that.

## Do-nots

- Do not recolour the mark or lockup — no theming, no tinting, no
  single-colour (all-white/all-black) variant. If a surface needs a
  monochrome mark, that is a new, deliberately-authored asset, not a CSS
  filter on this one.
- Do not stretch or skew either asset to a non-native aspect ratio. The mark
  is square (1:1); the lockups are 16:9. Scale uniformly only.
- Do not place the mark on a surface where any tile's contrast against the
  background drops below the token pairs' own audited ratios — the mark
  assumes the graphite (`--bg-subtle`) or white ground it was designed
  against, not an arbitrary photo or brand-colour background.
- Do not regenerate, re-prompt, or "touch up" any file here. A revision to
  the artwork itself is a new owner-approved generation, replacing these
  files wholesale under its own task — never an edit folded into unrelated
  work.
- Do not typeset the wordmark by hand from `docs/brand.md`'s palette table.
  "QPMatrix" as text is only ever the pre-rendered lockup PNGs above; there
  is no font name recorded for it (the generation prompt deliberately
  excluded naming one), so a hand-typeset reproduction cannot be verified
  against the original.

## Provenance

Generated via `agy` (Antigravity CLI) image generation. The mark was one of
three options generated from
`qpmatrix-logo.prompt.txt`'s brief (a 3×3 dot-matrix "Q" silhouette, violet
tiles, one cyan tile, graphite ground, no text/letters — explicitly built to
work alone as a favicon or avatar); the owner selected this one. The lockups
were generated from `lockup.prompt.txt` directly against the chosen mark,
instructed to keep it "pixel-faithful in shape, colours and proportions" and
to typeset "QPMatrix" with no font name recorded in the image. Every prompt
file that produced a committed asset travels with it, unmodified, for
provenance:

- `packages/tokens/brand/qpmatrix-logo.prompt.txt` — the mark
- `packages/tokens/brand/lockup.prompt.txt` — both lockups

These assets are the QPMatrix company identity, distinct from and unrelated
to the "QP" desktop-companion mascot used elsewhere in the estate (`qp-desktop`'s
tray/app icons) — the two are never interchangeable.
