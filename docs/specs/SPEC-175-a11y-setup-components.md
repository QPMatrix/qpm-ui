## 2. Summary

qpai-setup-app hand-rolls a masked secret field and a text-size control, and has no stepper or copy-with-feedback control, because the kit has none. These are generic, accessibility-heavy patterns every QPMatrix surface will need (first-run setup, admin settings, the desktop). This spec adds four registry items in the kit's own shape (component folder, registry item, stories, tests, audited accessibility block), so apps stop inventing them.

## 3. Goal

After this change, `@qpmtx/ui` exports `QPSteps`, `QPSecretInput`, `QPCopyField` and `QPDisplayPreferences`, each registered, storied, keyboard-tested and marked `accessibility.status: "audited"`.

## 4. Scope

**In scope:**

- `steps` — an ordered list of steps (label, optional description, state `completed | current | upcoming`), `aria-current="step"` on the current one, numbers or check icons, horizontal and vertical orientation, optional clickable completed steps (buttons, not links), reduced-motion-safe indicator transition. Not a wizard: it renders progress, it owns no navigation state.
- `secret-input` — an input for secret values (`type="password"` by default) with a visibility toggle button (`aria-pressed`, accessible name "Show"/"Hide" + the field label), `autocomplete="off"`/`spellcheck={false}`, no value in any DOM attribute other than the input, works inside the kit's `field` (label, description, error wiring by ids).
- `copy-field` — a read-only value (single or multi-line) with a copy button, a polite live region reporting Copied/Failed, keyboard reachable, clipboard failure selects the text for manual copy; never logs the value.
- `display-preferences` — a small panel: text size (segmented control, applied as a root font-size percentage through the tokens), reduced motion (switch; sets a root attribute the kit's motion honours), colour scheme (system/light/dark; applies the kit's theme contract). Persisted per viewer in `localStorage` behind a guarded adapter; renders correctly when storage throws.
- For each: `packages/ui/src/components/<name>/` (constants, types, utils, tsx, stories, test, index), registry item under `src/registry/items/<name>.ts`, export from the package index, `registry.json` regenerated by the repo's script, docs entry where the repo documents components.

**Out of scope:**

- Adopting them in qpai-setup-app (QPAI-174 wave two).
- A release tag (the orchestrator cuts it after review).
- Redesigning existing items.

## 5. Acceptance criteria

- **AC-1** — `bun run registry:validate` and `registry:check` pass with the four new items; `registry.json` lists them.
- **AC-2** — Each item has stories covering every state and a test file with keyboard interaction (Tab/Enter/Space; arrow keys where the pattern requires) and an axe-style assertion where the repo already uses one.
- **AC-3** — `QPSteps`: exactly one element carries `aria-current="step"`; completed steps expose their state to assistive tech (visually hidden text or `aria-label`), never colour alone.
- **AC-4** — `QPSecretInput`: toggling visibility keeps focus on the toggle, updates `aria-pressed` and the input `type`; the value never appears in a `data-*`, `title` or `aria-*` attribute.
- **AC-5** — `QPCopyField`: after copy, the live region text is the localised "Copied" message and the button's accessible name is unchanged; on rejection the text is selected and the region says "Copy failed".
- **AC-6** — `QPDisplayPreferences`: changing text size updates the root font-size percentage; enabling reduced motion sets the root attribute the kit's motion utilities read; the panel is a labelled `group` and every control has a visible label.
- **AC-7** — `./check` green (typecheck, lint incl. the a11y plugin, tests, registry checks, storybook build if it is in the gate).

### Interfaces / contracts

- Props are typed in each `<name>.types.ts`; no `any`; strings that reach users are props with English defaults so apps can localise.
- `display-preferences` persistence goes through a tiny adapter (`read/write` with try/catch); the component works with a no-op adapter.

### Dependencies / env vars

- None new. Reuse `field`, `label`, `button`, `icon-button`, `segmented-control`, `switch`, `motion-core`, `cn`, `theme-contract` as registry dependencies.

### Documentation impact

- The kit's component docs surface (find it under `docs/` or the package README) — four entries.
- `docs/specs/SPEC-175-a11y-setup-components.md` — this file, committed with the change.

## 7. Tests

- Per item: render, keyboard, state, and the negative cases named in AC-3..AC-6. Storybook stories are the visual contract; the existing `stories.test.tsx` harness must pick them up.

## 8. Risks

- The repo's scaffold script may generate a shape newer than `reveal/` — follow the scaffold, then match the newest existing item.
- `display-preferences` touching the document root must not fight the theme provider: read the kit's `theme-contract` and apply through it, never with ad-hoc classes.
